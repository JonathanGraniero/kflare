kflare {{ .Chart.AppVersion }} is installed in namespace {{ .Release.Namespace }}.

Check that the controller is running:

  kubectl -n {{ .Release.Namespace }} rollout status deployment/{{ include "kflare.fullname" . }}
{{- if .Values.autoscaling.enabled }}

A HorizontalPodAutoscaler runs {{ .Values.autoscaling.minReplicas }} to {{ .Values.autoscaling.maxReplicas }} replicas, depending on the pods' use, which it
reads from the metrics API (metrics-server). Without it, TARGETS shows <unknown>:

  kubectl -n {{ .Release.Namespace }} get hpa {{ include "kflare.fullname" . }}
{{- if ne (int .Values.replicaCount) 1 }}

replicaCount ({{ .Values.replicaCount }}) is ignored while autoscaling is on. To keep that many
replicas, set autoscaling.minReplicas instead.
{{- end }}
{{- end }}

Next, connect a Cloudflare account. Store an API token in a Secret and point a
CloudflareAccount at it:

  kubectl -n {{ .Release.Namespace }} create secret generic cloudflare-token \
    --from-literal=CF_API_TOKEN=<your-api-token>

  cat <<YAML | kubectl apply -f -
  apiVersion: kflare.dev/v1alpha1
  kind: CloudflareAccount
  metadata:
    name: my-account
  spec:
    accountID: <your-account-id>
    tokenSecretRef:
      name: cloudflare-token
      namespace: {{ .Release.Namespace }}
  YAML

  kubectl get cloudflareaccounts   # READY should become True
{{- if and .Values.metrics.enabled .Values.metrics.secure }}

Metrics are served over HTTPS, to callers allowed get on /metrics: bind your
Prometheus' ServiceAccount to the ClusterRole {{ include "kflare.fullname" . }}-metrics-reader
(kube-prometheus-stack's Prometheus already has that permission).
{{- end }}

Before uninstalling, delete your kflare resources while the controller is still
running, so it can clean up (or retain) the matching Cloudflare objects.
Guide: https://github.com/JonathanGraniero/kflare/blob/main/docs/deploy.md
